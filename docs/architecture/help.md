# Shared help service

Help is a wide, short glass shelf that rises along the bottom of the active workspace window, using clear Liquid Glass (`NSGlassEffectView`, `.clear` style for lensing) on macOS 26 and later and HUD material on earlier releases. It follows system appearance and Reduce Motion. One top row holds the provider menu, search, and a glass close button; a plain inset list grouped by category navigates topics, and it and the detail sit in an appearance-aware dimming well so text stays legible over clear glass; a transparent WKWebView renders the detail pane in React.

Calc and the Arbor outline (`arbor`) are the bundled providers. F1 and **Explore calc** open contextual help from a calc fence or inline expression. F1 inside the Arbor outline opens the outline provider (the page emits `help.browse` with `providerID: "arbor"`). F1 anywhere else opens the help browser: in a web editor the page gets the key first and emits `help.browse` when no binding claimed it, and `AppDelegate`'s key monitor handles native surfaces. F1 inside help closes it. **Help → Explore nvModern Help** and the `app.help.open` action browse the same providers from anywhere in the app. Global help is read-only; contextual help can insert examples and templates. Escape, the close button, and clicking back into any app window dismiss the drawer and restore focus. Arrow keys in search browse topics; Return inserts the selected template or first example when the context permits it.

## Content and providers

`NVModern/WebEditor/src/lib/help/model.ts` defines portable `HelpProvider`, `HelpTopic`, and `HelpOpenRequest` interfaces. A topic contains its title, category, description, search keywords, signatures, aliases, examples, insertion actions, and optional `shortcuts` (key/action pairs) for providers that teach keys rather than syntax. Descriptions and code are plain data rendered as React text, never executable HTML. `NVModern/Core/HelpContent.swift` is the matching Codable model and native search implementation.

`src/lib/calc/help.ts` adapts calc's existing catalog, including unit and multiplier aliases. `build.ts` writes providers to the bundled `help-catalog.json` and builds `help.html/js/css` as an IIFE for file-backed WebKit. This makes help available before any editor has opened; runtime metadata remains the source of truth for calc. Add future bundled providers to this generated array (`helpProviders` in `build.ts`). The same step writes `help/<provider>.md` through `renderHelpMarkdown`, and the `get_help` MCP tool (`app.help.get`) serves that Markdown so agents can read the docs without the UI. Arbor's keyboard rows are generated from `src/arbor/keymap.ts`, the same declarative tables `ArborSurface.tsx` dispatches through, so help cannot drift from the bindings. Only pointer gestures and typed triggers are listed by hand in `src/arbor/help.ts`. A test requires every binding to name an existing help topic or be marked `hidden`. Native features can also register a provider with `AppHelpService.shared.register(provider)`.

`src/help.tsx` renders descriptions, signatures, examples, and insertion controls. `src/help/help.css` keeps the page transparent so the native material shows through. The web detail renderer receives `help.showTopic` and `setHostAppearance` commands. It emits `help.insert` with a topic/action ID or `help.close`; the native controller resolves IDs against the current selection rather than accepting arbitrary source from the page.

## Native presentation

Call `AppHelpService.shared.present(providerID:in:canInsert:allowsMultiline:onInsert:onClose:)` with a view in the destination window. `providerID` selects the opening provider; supplying it also scopes insertion to that provider. Other providers remain browsable. `onInsert` receives the stored template. Omit insertion callbacks for read-only help. `presentFromActiveWindow()` is the global entry point.

`UI/Help/AppHelpService.swift` owns the drawer, its source view, presentation animation, and dismissal. The drawer is a borderless, transparent `HelpPanel` attached as a child window of the workspace window, the same pattern as quick capture: glass needs its own transparent window to sample what lies behind it, and SwiftUI's `NSHostingView` must not own (and re-order) the drawer's views. It moves with the window and re-anchors on resize; native tab switches and clicks into another window make that window key, which dismisses help. `HelpDrawerController` owns native controls and the React detail WebKit surface. Presenting another help request replaces the previous session. Closing the source window, detaching an editor, replacing its document context, invalidating its controller, or beginning WebKit navigation dismisses contextual help.

## Editor integration

`Nv3EditorExtensionsOptions.onHelpOpen` is an optional, app-agnostic callback. Calc passes the provider ID, opaque session token, insertion capabilities, and cursor anchor to it. Without a callback, F1 retains the standalone CodeMirror panel. Completions, hover documentation, argument hints, snippets, and editable snippet fields remain CodeMirror features in both hosts.

The nvModern adapter emits `help.open`. `EditorWebContentController` intercepts it, opens the shared drawer, and binds replies to the originating WebKit view and document context. It sends `help.insert` or `help.closed` back with the original token. The library's `applyCalcHelpInsertion` validates the token, current calc context, read-only state, and multiline restrictions before applying a CodeMirror snippet; `dismissCalcHelp` clears only the matching session. CodeMirror maps insertion positions through edits while help is open. Example braces are escaped for literal insertion; templates keep their snippet fields.

## Validation

Run `make typecheck-help`, `make typecheck-calc`, `make test-web`, and `make test TEST_ONLY=NVModernTests/AppHelpServiceTests`. Native tests load the bundled React page, verify descriptions and results, exercise insertion-action validation and empty search, and check source-bound dismissal without creating additional windows. `make` verifies the complete app and web bundle.
